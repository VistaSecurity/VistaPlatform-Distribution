    Starting your trial¶

    Every new install runs as Vista Platform Core with its free allowance: 100 assets, 1 sensor, 1 device agent and 3 users. A platform admin can lift that for 30 days: every capability on, at Pro's capacity (10,000 assets, 50 sensors, 50 device agents, unlimited users), one trial per installation. This page is for the platform admin; it uses the admin console (admin-ui).

    Start the trial¶

    1. Sign in to the admin console as a platform admin (the platform.settings permission). On an install that has not had its trial, the Overview page shows a card, Start your free 30-day trial. The same card sits at the top of Settings → License & Usage while the trial is available.
    2. Fill in your name, work email address and company name, and a phone number if you want to give one. The trial is free; in exchange, Vista Security may contact you by email or phone about your evaluation and Vista Platform. Tick I agree that Vista Security may contact me about Vista Platform (the button stays disabled until you do), then click Start 30-day trial.
    3. The console reloads with every capability on and the card replaced by "Trial active, 30 days left". Nothing is pasted and no account is created.

    The card also shows the install ID, the identifier the trial is issued for. You will want it if you ever contact Vista Security about this install.

    What the install sends, and what arrives¶

    To start a trial, the install sends the licensing service at licensing.vistasecurity.io: the install ID, the public half of the install's report-signing key, the database's system identifier (and the kube-system namespace UID, where the install can read it), your name, email address, company and phone (if given), your agreement to be contacted and the version of the privacy notice it was given under, the platform version and whether it runs on Kubernetes or Docker Compose. The install does not keep your name, company or phone: they go to the licensing service only, and are not written to the install's database, audit log or logs (the audit log records only the domain of the email). The service answers with a signed trial licence, which the install checks against the keys built into the release before using it. The licence carries only the domain of your address. The same answer is shown in the console, so there is no paste-the-token step and no mail round trip.

    The licensing service also sends a welcome email to the address you entered. Separately, the install emails the platform admins about the licence itself; see Installing and renewing a licence. Those emails need email delivery configured on the install; the same notices appear as banners either way. The privacy notice for these details (what Vista Security uses them for, how long it keeps them, and how to stop contact or have them deleted by writing to sales@vistasecurity.io) is in TERMS.

    Why a trial can be refused¶

    The card says why, in plain words:

    • This installation already had its trial. One trial per installation: the licensing service refuses a second for the same install ID, the same database or the same cluster. Contact sales@vistasecurity.io for a licence.
    • Use a work email. Free-mail and disposable domains are not accepted. A work domain gets at most two unexpired trials and three in a year.
    • Trial limit reached. The card names the limit: too many trial requests from your network (try again later), or your organisation's email domain has used its trials (contact sales@vistasecurity.io).
    • This installation is already licensed. A trial would grant nothing more.
    • Check the trial details. A name or company is missing or too long, the phone is not a phone number, or the agreement to be contacted is not ticked.

    If the install cannot reach the licensing service¶

    The card then reads "Couldn't reach the licensing service" and nothing has been granted. It shows the identifiers a licence is issued for: the install ID, the database identifier and, where readable, the cluster UID. The air-gapped path is:

    1. Copy the install ID (and the other identifiers) from the card.
    2. Request the trial through the web form at https://vistasecurity.io/licence or by email to sales@vistasecurity.io, quoting them.
    3. A token file arrives by email.
    4. Open Settings → License & Usage, paste the token file under Install a token file and click Install token. This is the only place a paste exists.

    If this install can never reach the licensing service, tick Air-gapped (no refresh) under Licensing service on the same page, so it does not try. See Installing and renewing a licence. A running install never depends on the licensing service except to refresh a licence.

    While the trial runs¶

    Tenant admins see a banner in the web console while a trial is running, and again when it is close to its end; they can dismiss it for the day. The trial card turns into the licence summary on Settings → License & Usage: the edition, the expiry and the days left. The console warns in the last seven days and the install emails the platform admins then.

    On day 31¶

    A trial has no grace period. At the expiry in the licence, the install returns to the Core allowance. Nothing is deleted and nobody is locked out.

    • Assets. The 100 most recently seen assets stay in the inventory. The rest are held in Discovery → Review → Approvals, marked "over the Core allowance", with their history intact. You can choose which assets stay: Demote an admitted asset to free a place, Promote a held one into it. The admitted count never exceeds the allowance.
    • Sensors and device agents. The most recently active sensor and the most recently active device agent stay active. The others are paused but stay enrolled. On Discovery → Sensors & Agents use Pause and Resume to swap which one is active.
    • Users. Everyone can still sign in. New invitations wait until you are under the allowance.
    • History. No history is deleted because a trial or a licence ended. The per-edition retention period is not enforced in 6.0.0, so nothing is trimmed to the Core period. The banner and the email to the platform admins name a date 14 days after the drop and suggest exporting the audit log and the change log before it; in 6.0.0 nothing is removed on that date. The audit and change history still follows the retention policy a platform admin sets under Security & Trust → Retention (365 days by default), as it does in every edition; see Data retention.
    • A licence restores everything. Install a paid licence and, on the next pass (within ten minutes), held assets are admitted with their history and paused agents resume.

    The trial is one per installation. To carry on past the allowance, buy a licence: see Editions and allowances and vistasecurity.io.
